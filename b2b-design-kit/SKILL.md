# 外贸网站设计助手

用户是外贸从业者，不懂设计术语。**让他们选，不让他们描述**：先推荐，再让他们挑；每次最多给 3–4 个选项；用编号沟通。

## 分工：结构和风格分两步定

- **内容**（五步法第 1 步、WordPress Builder 定）：导航、类目层级、产品、公司事实、每页要讲什么。
- **结构**（用户在「网站视觉实验室」里定）：首页、产品聚合页、详情页各放哪些模块、什么顺序，用哪些高光组件和动效。
- **视觉风格**（本 skill 调研后让用户选）：配色、字体、图片调性。实验室里的预览故意用中性灰白配色，提示词里的颜色和字体也只是占位，**不要照搬成最终风格**。这样每个站的风格从自己的行业和品牌出发，不会千篇一律。

## 模板库

本目录 `library.json`（全部中文）：
- **积木**：47 块（含页头 N1 标准页头、N3 超级菜单），编号 N、H、T、C、F、A、P、D、Q 开头
- **高光组件**：18 个（X01–X19）
- **动效**：12 个（M01–M12）
- **挂件**：3 个（W 开头，全站固定元素，如悬浮联系栏、询盘弹窗）
- **行业类型**：10 种（T01–T10），每种 3 套整页方案（A、B、C）
- **行业**：30 个（I01–I30）
- **风格参考**：`styles`（S01–S12）和质感 `textures`（G01–G05）。调研时可以参考，不要直接套用。

每个组件都有适用标签 `fit`：
- `pages`：适合哪些页面
- `pos`：建议位置（首屏、首屏下方、中段、页尾前、全站）
- `types`：最适合的行业类型
- `needs`：动效要搭配的积木

推荐或修改结构时按标签来：
- 不把详情页的积木放到首页
- 首屏只放 `pos` 为首屏的组件
- 页面上没有 `needs` 里的积木时，不加对应动效

`picker.html` 就是「网站视觉实验室」网页，可以直接用浏览器打开给用户。`images/web/<行业>/<角色>.jpg` 是 30 个行业的示例配图，只用于预览。

积木代码里的 `data-img` 标着每个图片位置要放什么：
- hero：首屏大图
- factory：工厂车间
- qc：质检测试
- product：主推产品
- cat1–cat4：四个类目
- app1–app2：应用场景

**语言**：实验室、提示词和预览都用中文，方便用户确认。正式网站的语言按建站简报来（外贸站通常是英文），实现时把中文样例换成目标语言的真实资料。

## 在整个建站流程里的位置

本 skill 是 WordPress Builder 的**外挂补丁**。**绝不修改 WordPress Builder 的任何文件、规则或它的项目记录格式**，只靠它自带的规则接上：
1. 「已有用户选定图稿时直接继续，不重复生成或确认」：用户确认的预览截图就是选定图稿，它不再出图。
2. 「用户明确要求跳过生图时按其要求执行并记录」：用户用实验室定了布局、用 HTML 预览选样，就是这种情况，在设计记录里写明即可。
3. 「在项目现有设计文档中标明选定图稿、对应路由和版本」：`design/design-spec.md` 就是这份设计文档。
4. 「选定设计的局部修正不重新启动出图选样」：以后按编号改模块，它不会推翻重来。

```
WordPress Builder：需求和页面架构（用户确认）
        ↓
网站视觉实验室：用户拖拽组合页面结构 → 复制提示词
        ↓
本 skill：读第 1 步资料和架构 → 布局 × 架构对照 → 风格调研 → 3 条风格样张 → 生成照片 → 整页 HTML 预览 → 自查 → 用户修改、确认 → 停下等「开始建站」
        ↓  交出 design/design-spec.md（含已选定图稿表）+ design/selected/*.png + design/preview/ + AGENTS.md 里的说明
WordPress Builder：按"已选定图稿"实现，样式变量、照片和交互代码从 design/preview/ 取
```

**为什么不整页生图**：布局已经在实验室定好，AI 整页画图会漏模块、丢小字、写错中文，改一处还会让风格漂移。HTML 预览照代码拼，模块和文字一个不少，交互和手机端都是真的，改样式只改变量。生图工具只用来生成照片，这是它最擅长的。

本 skill 不写 WordPress 模板、不改 ACF、不部署。实现、后台可编辑、询盘、上线都由 WordPress Builder 负责。

## 和五步法的配合（群鱼学院课程）

| 五步法 | 谁负责 | 本 skill 做什么 |
|---|---|---|
| 第 1 步 研究与架构 | WordPress Builder | 不参与。它产出的资料、网站树状架构、每页目的和模块顺序、同行参考，是本 skill 的输入 |
| 第 2 步 确认设计 | 用户选路线：直接出图走 WordPress Builder；挑布局走实验室 + 本 skill | 只在实验室路线工作：布局 × 架构合并 → 风格 → 照片 → HTML 预览 → 归档，然后停下 |
| 第 3–5 步 建站、部署、域名 | WordPress Builder | 不参与。它从 design-spec.md 和 design/selected/ 读取定稿 |

一句话分工：**第 1 步定「放什么」，实验室定「长什么样」，本 skill 把两者合起来做成预览，WordPress Builder 负责做成真网站。**

## 一、用户还没定结构

直接让用户去「网站视觉实验室」挑布局：线上 https://qunyuai.com/lab ，或本目录的 `picker.html`。选行业、套一套整页方案、拖拽调整，点「复制提示词」粘贴回来。

**不要在对话里另外给几种首页排法让用户选**，否则用户要在对话里选一次、实验室里再选一次。只有用户明确说「你帮我推荐」时，才按行业类型列出 `library.json` 里的 A、B、C 三套方案，每套一句话说明适合谁。

## 二、收到结构方案：合并架构 → 风格 → 照片 → HTML 预览 → 自查

收到【网站视觉实验室 · …】（或旧版【设计实验室 · …】）开头的提示词时，里面已经写了完整步骤和代码，**照做**。要点如下。

1. **先读第 1 步的成果，再记录**
   - 读项目里已确认的资料、网站树状架构、每类页面的目的和模块顺序、研究过的同行。找不到就问用户放在哪，不要凭实验室样例猜。
   - 整段保存到 `design/design-spec.md`，第一行写设计码。
   - 单个组件或动效的提示词是**修改**：只更新 design-spec.md 里对应的部分；已有 `design/preview/` 的话同步加进预览。没说放哪一页、哪个位置时，问用户一次，给出 2–3 个可选位置。
2. **让布局迎合架构和资料：只加不减（自动完成，不停下来问用户）**
   - **用户在实验室选的模块全部保留**，顺序不变，一个都不删。缺资料的模块在原位置照常显示，**用逼真的示例内容填满**（示例数字、评价、客户名、AI 示例照片），看起来和正式网站一样，轮播、滚动等效果也保留。不写 Pending/待补充 占位字、不用灰框、不调低透明度；哪些是示例只靠预览标签（`data-mod-state="示例·待补充"`）和待补充清单标出。示例内容只用于预览。不要把模块挪去放别的内容。
   - 导航、类目名称和层级、产品、公司事实全部按第 1 步，不用实验室样例。
   - **资料比布局多时扩展布局**：类目超过 5 个或有二级类目，页头换成 N3 超级菜单；类目卡、产品卡、图文行、FAQ 按真实数量加行；一级、二级类目用途不同时，分别做一级类目页和二级类目页；架构要求、布局里没有的内容，按 `fit` 标签从 `library.json` 挑最合适的模块自动加上。
   - 资料比布局少时，卡片按真实数量显示，不硬凑假内容。
   - 第 1 步确认过的固定要求优先，例如类目页和详情页下部用 D8「图文正文 + 悬浮询盘」。
   - 结果写进 design-spec.md 的「布局 × 架构对照」：模块编号 → 放第 1 步的哪项内容 → 状态（有资料 / 待补充 / 新增），另列「待补充清单」。用户之后说「删掉 T1」「隐藏 X09」再删，设计码同步更新。
3. **风格调研**
   - 优先复用第 1 步研究过的同行，再补优秀 B2B 网站，**必须提出 3 个视觉风格方向（正好 3 个，不能少）**，三个要明显不同：明暗（浅底或深底）、字体气质、图片调性三项里至少两项不同，不要只换一个主色。
   - 每个方向写清：提示词第六部分 `:root` 里每个颜色变量的色值、标题和正文字体、圆角、图片调性、参考网站、为什么适合。
   - 可以参考 `library.json` 的 `styles` 和 `textures`，但要按客户调整，不要原样套。
4. **风格样张**（只看首屏判断不了整体）
   - 每个方向做一条样张，从上到下：① 首屏；② 一个产品或类目卡片区；③ 一个强调色或深色区块（询价横幅、数据条等）；④ 页脚。用布局里对应的模块和第 1 步的真实内容，布局里没有的用实验室同类模块。
   - 每个方向先生成 1–2 张关键照片（首屏图、一张产品图），其余位置复用。
   - 三条样张放进 `design/preview/style-compare.html`，标上方向名，每个方向截一张图。
   - 把三张样张截图发给用户选方向，同时说明布局按架构新增了什么，以及待补充清单（不需要用户逐条确认）。选定后写进 design-spec.md 的「视觉风格」一节。
5. **生成照片**
   - 样张里已生成的照片直接复用。用 Codex 的生图工具，按第 1 步的真实产品和场景补齐照片（提示词第五部分是示例描述），存到 `design/preview/images/<位置>.jpg`。用户有真实照片时优先用真实照片。
   - 色调、光线统一。照片里不要文字、logo、证书和可辨认的人脸。首屏和场景图用横版，产品图用干净背景。
6. **整页 HTML 预览：先首页，再其他页**
   - 先做 `design/preview/home.html`，用户确认首页后，再沿用同一套风格做 `category.html`、`detail.html`。三页共用 `preview.css` 和 `preview.js`，双击能打开，不依赖外部网络。
   - 直接用提示词第六部分（或 `library.json`）的参考代码拼：模块按对照表最终的模块和顺序，**一个都不能漏**；**只改 `:root` 样式变量**，不改模块结构。
   - **每页都是完整、能当最终效果看的页面**：页头页脚等模块用参考代码的完整结构，不简化；卡片至少放满一行，产品聚合页产品卡 6 张以上。
   - **页面太单薄时按页面类型补全**（标「新增」）：产品聚合页至少有类目横幅、二级类目或筛选、产品卡、D8、信任或认证条、FAQ、询价横幅、页脚；详情页至少有图库首屏、参数、D8、应用场景、相关产品、FAQ、询价横幅。
   - 内容按对照表放第 1 步的真实资料；「页面文字」是文字清单和字数参考，小字也要有。缺资料的位置用逼真的示例内容填满，由标签标出，不删模块。
   - `data-img` 换成照片。没有真实素材的模块也要显示：logo 用示例品牌字标，证书用示例证书样式，视频用示例封面加播放按钮；每个图片位置都要有照片，没有真实照片用 AI 示例照片，不留灰框。「没内容时整块不显示」只用于正式网站。
   - 加上选中的动效和挂件代码。
   - **预览专用编号标签**：每个模块最外层加 `data-mod="编号" data-mod-name="名称"`，用了示例内容的加 `data-mod-state="示例·待补充"`，自动新增的加 `data-mod-state="新增"`；把提示词第六部分「预览专用：模块编号标签」的代码放进 preview.css 和 preview.js。预览里每块左上角显示编号和状态，用户一看就知道删哪块。
7. **自查**
   - 用浏览器（无头 Chrome 或 Playwright）按 1440px 和 390px 宽截整页图，存到 `design/preview/shots/`。
   - 按 `references/review.md` 检查：模块齐全、内容和对照表一致、页面文字齐全、没有控制台报错、交互能用、手机不挤坏，再看 8 条审美标准。
8. **给用户看**
   - 每页只发一张**带编号标签**的电脑端整页截图（Markdown 图片），同时列出待补充清单，附上 HTML 文件位置，告诉用户可以双击打开试交互、缩窄窗口看手机效果。
   - 用户按编号或白话修改，改完重新截图。

## 三、用户说"不好看"：翻译成设计问题

用户常说"太乱""太空""廉价""不大气"。按 `references/translate.md` 把感觉翻译成设计问题，给 2 个改法让用户选，**一次只改一处**。

- 结构问题（模块多了、顺序不对）：改 design-spec.md 的页面结构。
- 风格问题（颜色、字体、气质）：回到风格方向调整。
- 用户说编号（"首屏换 X01""去掉 M09"）：直接改预览，再重新截图。

## 四、用户确认：交给 WordPress Builder

1. 三页都确认后，先按用户的决定删掉不要的模块，再用 `?clean` 打开每页（如 `home.html?clean`），截**不带编号标签**的电脑端整页截图，存到 `design/selected/`：`home.png`、`category.png`、`detail.png`。这就是 WordPress Builder 说的「已选定图稿」。`design/preview/` 保留，作为实现时的样式和交互依据。
2. 在 design-spec.md 末尾加「已选定图稿」表，写上选定的视觉风格（色值、字体），并注明「本项目用 HTML 预览选样，图稿是用户确认过的预览截图」：

   | 页面 | 网址 | 图稿文件 | HTML 预览 | 日期和版本 |
   |---|---|---|---|---|
   | 首页 | / | design/selected/home.png | design/preview/home.html | 2026-11-20 · 设计码 · v1 |

3. 在网站项目根目录的 `AGENTS.md` 末尾追加下面这段（没有就新建，**不改原有内容**）。Codex 每次开工都会自动读它，新开对话也能接上：

   > 本项目设计已选定：设计记录见 design/design-spec.md，图稿在 design/selected/，HTML 预览在 design/preview/（样式变量、模块结构和交互代码的实现依据）。按 WordPress Builder 规则这是已选定图稿，直接实现，不重新生图；局部修改只改受影响的部分。

   以后改了设计，同步更新预览、截图和表里的版本日期。
4. 告诉用户采用清单和文件位置，**然后停下**（对应五步法第 2 步结束）。等用户说「开始建站」，再交给 WordPress Builder：

   > 设计已选定。接下来按 WordPress Builder 实现：这是"已选定图稿"，直接按图实现，不重新生图。

   实现时必须遵守 design-spec.md 里的"实现要求"：
   - 文字换成真实资料，缺的标"待补"
   - 参考代码转成主题模板和 ACF 后台可编辑字段
   - 颜色字体用选定的风格（design/preview/ 里的样式变量）
   - 保留询盘表单、来源记录、多语言切换、在线聊天
   - 空模块整块不显示
5. 预览专用的编号标签（`data-mod`、`pv-tag`、`pv-toggle`）只留在 `design/preview/`，**不要带进主题和正式网站**。
6. 动效和高光组件的代码放进主题：CSS 进主题样式，JS 进主题脚本并在页脚加载。积木类名可以保留 `b-xx` 前缀，方便以后按编号改。

## 高光组件

- 高光组件（X 开头）是让页面"有灵魂"的交互模块，共 18 个，例如：轮播、视频首屏、滚动叙事、横向滚动、360° 查看、出口地图、前后对比、卡片轮播、评价轮播、超大滚动字、放大镜、数字仪表盘、视频弹窗、光晕卡片、叠层卡片、逐字浮现首屏。
- 它们的交互代码（JS）在提示词里，**实现时照着代码做出真实交互**，不要做成静态图。轮播、地图等内容要在后台可编辑。
- 一页最多 2 个高光组件。首屏只能有一个：H 开头的首屏，或 X01 轮播、X02 视频、X16 逐字浮现三选一。
- X02 视频、X13 视频弹窗需要用户提供视频；没有视频时显示封面图，并在 design-spec.md 里标"待补视频"。
- X06 地图里的出口国家必须是用户真实出口的国家。

## 规则

- **不影响 WordPress Builder**：不修改它的文件、规则和项目记录，只在网站项目里写 `design/` 和 AGENTS.md 末尾的说明。没用实验室、项目里也没有 design/design-spec.md 时，用户说"出设计图"就交给 WordPress Builder 自己的出图流程，照它原来的方式整页生图。实现、后台字段、询盘、部署都不归本 skill 管。
- **不编事实**：预览和页面上的公司名、数字、认证、客户 logo、评价都只能来自用户资料。库里的样例（澳华阀门、"40+ 出口国家"等）是虚构的，只用来预览。
- **同一个网站项目只开一个会写文件的对话**。设计和实现都在原网站项目里进行，不新建项目。
- 动效一个站保持 2–3 个。严肃行业（化工、医疗、物流）不推荐 M09 3D 倾斜。
- 用户已经有满意的设计图（自己做的或 WordPress Builder 出的），或明确说跳过选择时，直接把图存进 `design/selected/` 交给 WordPress Builder，不强迫走选择流程。
- 和用户说话用中文白话，少用术语；必须用术语时附一句解释（例如"留白：模块之间的空白"）。
