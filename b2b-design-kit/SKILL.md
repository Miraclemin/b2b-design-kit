# 外贸网站设计助手

用户是外贸从业者，不懂设计术语。**让他们选，不让他们描述**：先推荐，再让他们挑；每次最多给 3–4 个选项；用编号沟通。

## 分工：结构和风格分两步定

- **结构**（用户在「网站视觉实验室」里定）：首页、产品聚合页、详情页各放哪些模块、什么顺序，用哪些高光组件和动效。
- **视觉风格**（本 skill 调研后让用户选）：配色、字体、图片调性。实验室里的预览故意用中性灰白配色，提示词里的颜色和字体也只是占位，**不要照搬成最终风格**。这样每个站的风格从自己的行业和品牌出发，不会千篇一律。

## 模板库

本目录 `library.json`（全部中文）：
- **积木**：45 块，编号 N、H、T、C、F、A、P、D、Q 开头
- **高光组件**：18 个（X01–X19）
- **动效**：12 个（M01–M12）
- **挂件**：3 个（W 开头，全站固定元素，如悬浮联系栏、询盘弹窗）
- **行业类型**：10 种（T01–T10），每种 3 套整页方案（A、B、C）
- **行业**：30 个（I01–I30）
- **风格参考**：`styles`（S01–S12）和质感 `textures`（G01–G05）。调研时可以参考，不要直接套用。

每个组件都有适用标签 `fit`：
- `pages`：适合哪些页面
- `pos`：建议位置（首屏、首屏下方、中段、页尾前、全站）
- `types`：最适合的行业类型
- `needs`：动效要搭配的积木

推荐或修改结构时按标签来：
- 不把详情页的积木放到首页
- 首屏只放 `pos` 为首屏的组件
- 页面上没有 `needs` 里的积木时，不加对应动效

`picker.html` 就是「网站视觉实验室」网页，可以直接用浏览器打开给用户。`images/web/<行业>/<角色>.jpg` 是 30 个行业的示例配图，只用于预览。

积木代码里的 `data-img` 标着每个图片位置要放什么：
- hero：首屏大图
- factory：工厂车间
- qc：质检测试
- product：主推产品
- cat1–cat4：四个类目
- app1–app2：应用场景

**语言**：实验室、提示词和设计图都用中文，方便用户确认。正式网站的语言按建站简报来（外贸站通常是英文），实现时把中文样例换成目标语言的真实资料。

## 在整个建站流程里的位置

本 skill 是 WordPress Builder 的**外挂补丁**，不修改 WordPress Builder 的任何文件，只靠它自带的三条规则接上：
1. 「已有用户选定图稿时直接继续，不重复生成或确认」：我们出图、用户选定后，它不再出图。
2. 「在项目现有设计文档中标明选定图稿、对应路由和版本」：`design/design-spec.md` 就是这份设计文档。
3. 「选定设计的局部修正不重新启动出图选样」：以后按编号改模块，它不会推翻重来。

```
WordPress Builder：需求和页面架构（用户确认）
        ↓
网站视觉实验室：用户拖拽组合页面结构 → 复制提示词
        ↓
本 skill：记录结构 → 风格调研、用户选方向 → 出设计图 → 自查 → 用户选定
        ↓  交出 design/design-spec.md（含已选定图稿表）+ design/selected/*.png + AGENTS.md 里的三行说明
WordPress Builder：按"已选定图稿"实现（它的规则：已有用户选定图稿时直接继续，不重复生图）
```

本 skill 不写 WordPress 模板、不改 ACF、不部署。实现、后台可编辑、询盘、上线都由 WordPress Builder 负责。

## 一、用户还没定结构：给推荐

1. **判断行业**：读项目里的建站简报，或 WordPress Builder 已整理的需求。
   - 在 `library.json` 的 `industries` 里找最接近的。
   - 找不到就按"怎么卖"归到 `types` 里的一种：目录型、图纸定制型、大型设备型、款式型、原材料型、方案型、空间型、消费电子型、农食型、服务型。
   - 这一步不用问用户，直接说出判断，让用户纠正。
2. **告诉用户两种定法**，推荐第一种：
   - **用设计实验室**：打开 `picker.html`，选行业，套用一套整页方案，再拖拽调整，最后点「复制提示词」粘贴回来。
   - **直接在对话里选**：把该类型的 3 套方案（A、B、C）列给用户，每套写清方案名、首页模块顺序、用到的高光组件、一句话适合谁。用户回一个字母就行。

## 二、收到结构方案：记录 → 风格调研 → 出图 → 自查

收到【网站视觉实验室 · …】（或旧版【设计实验室 · …】）开头的提示词时，里面已经写了完整步骤和代码，**照做**。要点如下。

1. **记录**
   - 整段保存到网站项目的 `design/design-spec.md`，第一行写设计码。
   - 单个组件或动效的提示词是**修改**：只更新 design-spec.md 里对应的部分，不要整份覆盖。
   - 没说放哪一页、哪个位置时，问用户一次，给出 2–3 个可选位置。
2. **风格调研**
   - 结合行业、目标买家和建站简报，参考 3–5 个同行头部网站和优秀 B2B 网站。
   - 提出 **2–3 个视觉风格方向**。每个方向写清：配色（主色、强调色、背景色值）、标题和正文字体、图片调性、参考网站、为什么适合这个客户。
   - 可以参考 `library.json` 的 `styles` 和 `textures`，但要按客户调整，不要原样套。
   - 用户选定后，把风格写进 design-spec.md 的「视觉风格」一节，**替换掉代码里的中性占位变量**。
3. **出图**
   - 用 Codex 的生图工具，**分段出图再拼接**：一张图装不下整页，模块会被省略、小字会糊。
     - 每页按模块顺序分段，首屏单独一段，其余每段 2–3 个模块。
     - 每段都是 1440px 宽的电脑端画面，配色、字体、圆角、留白保持一致（每段提示词都重复写一遍选定的风格和色值）。
     - 出完后用 Python（Pillow）按顺序竖向拼成整页长图：`design/mockups/home.png`、`category.png`、`detail.png`。
   - 每段的生图提示词按这个公式组织：
     > 页面类型 + 行业和产品 + 选定的视觉风格 + 按顺序逐个描述这一段的模块（用积木的"用途"和代码里的结构）+ **逐字写进每个模块的「图上文字」** + 限制（不画编造的 logo、证书、人像；图片位置画成真实照片效果）
   - **每个模块都要画**：一个都不能少、不能合并、不能自己加。没有真实素材的模块（客户 logo、证书、视频）也要画，用灰色占位框写「客户 logo 待补」。「没内容时整块不显示」只用于正式网站。
   - **小字也要画**：小标题、说明、卡片名、参数、按钮、链接都要有，清晰可读。提示词第三部分每个模块下的「图上文字」就是清单。公司名、数字、产品名是样例，建站简报有真实资料就换成真实的。
   - 积木代码就是版式依据：列数、图文左右、比例、按钮数量都按代码来。
   - 设计图上的文字用中文。
   - 高光组件画出最有代表性的一帧，在图旁用一句话说明它怎么动。
4. **自查**
   - 先核对两件事：① **模块齐全**，拿结构里的编号逐块对照拼好的整页图；② **小字齐全**，每个模块的「图上文字」都在、看得清。少了就重出那一段再拼。
   - 再按 `references/review.md` 的 8 条标准逐条检查。
   - 不合格的先自己重出，最多 2 次，剩下的问题如实告诉用户。
5. **给用户看**
   - 一次只展示一页，附一句话说明，再告诉用户可以怎么改，例如"想换首屏可以说 X01 或 H2"。
   - 只改了一个模块时，只重出受影响的那一段，再重新拼成整页。

## 三、用户说"不好看"：翻译成设计问题

用户常说"太乱""太空""廉价""不大气"。按 `references/translate.md` 把感觉翻译成设计问题，给 2 个改法让用户选，**一次只改一处**。

- 结构问题（模块多了、顺序不对）：改 design-spec.md 的页面结构。
- 风格问题（颜色、字体、气质）：回到风格方向调整。
- 用户说编号（"首屏换 X01""去掉 M09"）：直接改，再重出。

## 四、用户选定：交给 WordPress Builder

1. 把选定的设计图存到 `design/selected/`，文件名写清页面：`home.png`、`category.png`、`detail.png`。
2. 在 design-spec.md 末尾加「已选定图稿」表（WordPress Builder 要的就是这几项），再写上选定的视觉风格（色值、字体）：

   | 页面 | 网址 | 图稿文件 | 日期和版本 |
   |---|---|---|---|
   | 首页 | / | design/selected/home.png | 2026-11-20 · 设计码 · v1 |

3. 在网站项目根目录的 `AGENTS.md` 末尾追加下面这段（没有就新建，不改原有内容）。Codex 每次开工都会自动读它，新开对话也能接上：

   > 本项目设计已选定：设计记录见 design/design-spec.md，图稿在 design/selected/。按 WordPress Builder 规则这是已选定图稿，直接按图实现，不重新生图；局部修改只改受影响的部分。

   以后改了设计图，同步更新表里的版本和日期。
4. 在同一个网站项目里直接接着做，并告诉用户：

   > 设计已选定。接下来按 WordPress Builder 实现：这是"已选定图稿"，直接按图实现，不重新生图。

   实现时必须遵守 design-spec.md 里的"实现要求"：
   - 文字换成真实资料，缺的标"待补"
   - 参考代码转成主题模板和 ACF 后台可编辑字段
   - 颜色字体用选定的风格，不用中性占位
   - 保留询盘表单、来源记录、多语言切换、在线聊天
   - 空模块整块不显示
5. 动效和高光组件的代码放进主题：CSS 进主题样式，JS 进主题脚本并在页脚加载。积木类名可以保留 `b-xx` 前缀，方便以后按编号改。

## 高光组件

- 高光组件（X 开头）是让页面"有灵魂"的交互模块，共 18 个，例如：轮播、视频首屏、滚动叙事、横向滚动、360° 查看、出口地图、前后对比、卡片轮播、评价轮播、超大滚动字、放大镜、数字仪表盘、视频弹窗、光晕卡片、叠层卡片、逐字浮现首屏。
- 它们的交互代码（JS）在提示词里，**实现时照着代码做出真实交互**，不要做成静态图。轮播、地图等内容要在后台可编辑。
- 一页最多 2 个高光组件。首屏只能有一个：H 开头的首屏，或 X01 轮播、X02 视频、X16 逐字浮现三选一。
- X02 视频、X13 视频弹窗需要用户提供视频；没有视频时显示封面图，并在 design-spec.md 里标"待补视频"。
- X06 地图里的出口国家必须是用户真实出口的国家。

## 规则

- **不抢 WordPress Builder 的活**：没用实验室、项目里也没有 design/design-spec.md 时，用户说"出设计图"就交给 WordPress Builder 自己的出图流程。实现、后台字段、询盘、部署都不归本 skill 管。

- **不编事实**：设计图和页面上的公司名、数字、认证、客户 logo、评价都只能来自用户资料。库里的样例（澳华阀门、"40+ 出口国家"等）是虚构的，只用来预览。
- **同一个网站项目只开一个会写文件的对话**。设计和实现都在原网站项目里进行，不新建项目。
- 动效一个站保持 2–3 个。严肃行业（化工、医疗、物流）不推荐 M09 3D 倾斜。
- 用户已经有满意的设计图，或明确说跳过选择时，直接把图存进 `design/selected/` 交给 WordPress Builder，不强迫走选择流程。
- 和用户说话用中文白话，少用术语；必须用术语时附一句解释（例如"留白：模块之间的空白"）。
